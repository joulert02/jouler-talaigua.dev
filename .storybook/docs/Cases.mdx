# Case pages

<StatusBadge status="approved" />

How to assemble a case study from content alone, without touching code. The parts every case shares live in `src/components/projects/case/` (Storybook: `Components/Projects/Case/…`). The first case built this way is Brand platforms (HU-04, `src/content/projects/*/brand-platforms.mdx`); the sealed design is `docs/design/v11/work/brand-platforms/`.

## Turning a case on

Each project has one file per language in `src/content/projects/en/` and `src/content/projects/es/`. A case is built when:

1. The file is `.mdx` (rename it from `.md`).
2. Its frontmatter says `case: live` (`coming` keeps the short "coming soon" page).

The route `/work/<slug>/` (and `/es/work/<slug>/`) then renders `WorkCase`: the case top bar (back pill and language switch), the header from `title` and `company`, the MDX body, and the previous and next case in Work order. The title morphs from its row on Work. Nothing else needs to change.

## The body, in order

Write plain Markdown for paragraphs; WorkCase renders every paragraph as `CaseParagraph`, and each block below sets its size. Markdown links render as `CaseLink`: a full URL (`[TENA](https://www.tena.com.co/)`) opens in a new tab with an arrow. Import the blocks at the top of the MDX with the `@/components/...` alias.

| Block                                 | What it holds                                                                                                                                                                                                                                                                                                                                                                                               |
| ------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `<CaseFacts>` with `<Fact label="…">` | The facts strip: usually Role, the brands or scope, and Stack. Labels are content, so each language writes its own.                                                                                                                                                                                                                                                                                         |
| `<CaseIntro title="…" layout>`        | The opening: its heading ("What I learned", or the case's headline), the text and a `<CaseQuote>` as Markdown, and the media in `slot="media"`. `layout`: `portrait` (a phone-shaped video, the default) or `side` (a landscape image beside the text; on phones it sits between the paragraph and the quote) or `photo` (a square photo centred with one paragraph; on tablets the quote goes below both). |
| `<CaseFigure slot="media" src alt>`   | A landscape image for the intro or a chapter, with an optional caption.                                                                                                                                                                                                                                                                                                                                     |
| `<CaseQuote>`                         | The owner's words, as Markdown paragraphs.                                                                                                                                                                                                                                                                                                                                                                  |
| `<CaseVideo slot="media" …>`          | A portrait video: files in `public/video/`, H.264 MP4 as the fallback, WebVTT tracks in both languages, `duration` in seconds.                                                                                                                                                                                                                                                                              |
| `<Chapter id number title lead>`      | One chapter: its interactive piece first, then `<FullStory>`.                                                                                                                                                                                                                                                                                                                                               |
| `<FullStory>`                         | "The full story": the approved paragraphs, unchanged, as Markdown.                                                                                                                                                                                                                                                                                                                                          |
| `<ExampleFrame id label shortLabel>`  | The frame for a playground, something the reader operates: label, controls, the piece, hints and notes (`ExampleHint`, `ExampleNote`) and actions. On phones it shows `shortLabel` centred on one line and stretches the controls.                                                                                                                                                                          |

**The top and the end** (owner review, 2026-11-23). A case has no bar of its own, so the reading stays on the project. The way back is the first step of the header's label, "Work / Company", with an underline drawn on hover; the language pill sits top right as on every other page. Cases hide the Dock. On phones (up to 560px) `CaseTop` takes over: the back pill and the language switch, hidden while scrolling down and back when scrolling up; the label then starts at the company. The chapters are reached from `CaseIndex`, a static line of links under the facts, always on one line; phones (under 720px) do not show it (owner review, 2026-11-25). Nothing floats over the page. At the end, `CaseNext` and the footer share the layout's columns (`--layout-gap`): the previous case in the left half, the next in the right half, and the footer's Contact column under it. `CaseTop` is also the whole top of coming-soon cases.

A playground specific to one case lives in that case's module, `src/components/projects/<case-slug>/` (Storybook: `Components/Projects/<Case>/…`), and composes ExampleFrame, with its copy per language in a config file next to it (`brand-platforms/PetysPlayground`, `TenaPlayground`, `NosotrasPlayground`). The MDX only places it: `<PetysPlayground />`.

## Rules

The owner's "Minimal and typographic" rules in `docs/design/principles.md` come first: every element earns its place, typography carries the hierarchy, every block sits on the layout's columns, no decoration and no card inside a card. New visual decisions are shown as options, the owner chooses, then they are built. The rest come from the v11 design:

- **One grid.** Two-column blocks use the layout's halves and four-column ones its quarters, both with `--layout-gap`, so edges line up from the intro to the footer. A rule spans the block it closes (FullStory's spans the chapter; its text keeps `--measure-prose`).
- **Frames are for playgrounds.** A static piece (a screenshot, a quote, a post) stands on the page without an `ExampleFrame`, across the chapter's columns, with its link under it.

- **Labels** say what a piece is and whose code it is not ("Recreation of the shipped screens · not TENA code").
- **Actions:** the primary button runs the demo, has no icon (its words say what runs; owner review, 2026-11-25) and is always rightmost; links that leave the site are ghost, to its left, and open in a new tab.
- **Every interactive piece has a scripted path** (Publish a change, Run scenario, Show me) and announces its result.
- **Phones** always get the phone version of a Desktop/Mobile playground; the switch shows from 720px.
- **Third-party screens** keep their own palette in both themes and make no claims about the third party; credits go in an ExampleNote.
- **Live sites are linked, not embedded.** Brand sites block framing (CORS and frame policies), so a case shows captures or recreations plus "See it live ↗".
- **Third-party embeds load on click.** A social post shows our own excerpt first; the official embed (and its cookies) loads only when the reader asks, and then a link opens the original.
- **Private captures:** crop the operating system and browser chrome, and cover account numbers with a solid block, not a blur.
